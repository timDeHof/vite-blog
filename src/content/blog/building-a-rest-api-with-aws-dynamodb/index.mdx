# Building a REST API with AWS DynamoDB

AWS DynamoDB is a fully managed NoSQL database that provides single-digit millisecond performance at any scale. In this guide, we'll build a REST API using DynamoDB.

## Why DynamoDB?

- **Fully managed** - No servers to provision or manage
- **Single-digit millisecond latency** - Fast reads and writes
- **Infinite scaling** - Handles virtually unlimited throughput
- **Built-in security** - Encryption at rest, IAM integration

## Data Modeling

In DynamoDB, we design for access patterns rather than relationships:

```typescript
// Example: User table access patterns
interface User {
  userId: string;        // Partition key
  email: string;         // GSI for email lookups
  name: string;
  createdAt: number;    // Sort key for GSI
}
```

## Lambda + DynamoDB Integration

Here's how to connect Lambda with DynamoDB:

```typescript
import { DynamoDBClient, PutItemCommand, GetItemCommand } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient } from "@aws-sdk/lib-dynamodb";

const client = new DynamoDBClient({});
const docClient = DynamoDBDocumentClient.from(client);

// Create a new item
export const createItem = async (item: any) => {
  await docClient.send(new PutItemCommand({
    TableName: "MyTable",
    Item: item,
  }));
};

// Get an item by key
export const getItem = async (key: any) => {
  const result = await docClient.send(new GetItemCommand({
    TableName: "MyTable",
    Key: key,
  }));
  return result.Item;
};
```

## Best Practices

1. **Use partition keys wisely** - Avoid hot keys
2. **Leverage GSIs** - For secondary access patterns
3. **Use TTL** - Auto-expire old data
4. **Enable DAX** - For microsecond latency
5. **Enable point-in-time recovery** - Backup strategy

## Conclusion

DynamoDB is an excellent choice for serverless applications. Its managed nature and performance characteristics make it ideal for cloud-native REST APIs.
