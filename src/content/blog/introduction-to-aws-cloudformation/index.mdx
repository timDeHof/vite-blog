# Introduction to AWS CloudFormation

Infrastructure as Code (IaC) is essential for modern cloud development. AWS CloudFormation lets you define your AWS infrastructure in code.

## What is CloudFormation?

CloudFormation is a service that helps you model and set up AWS resources so you can spend less time managing those resources and more time focusing on your applications.

## Template Anatomy

```yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: "My CloudFormation Template"

# Parameters - Customizable values
Parameters:
  EnvironmentType:
    Type: String
    Default: dev
    AllowedValues:
      - dev
      - staging
      - prod

# Mappings - Lookup tables
Mappings:
  RegionMap:
    us-east-1:
      AMI: "ami-12345678"
    us-west-2:
      AMI: "ami-87654321"

# Resources - AWS resources to create
Resources:
  MyS3Bucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Sub "my-app-${EnvironmentType}"
      VersioningConfiguration:
        Status: Enabled
      Tags:
        - Key: Environment
          Value: !Ref EnvironmentType

# Outputs - Values to expose
Outputs:
  BucketName:
    Description: Name of the S3 bucket
    Value: !Ref MyS3Bucket
    Export:
      Name: !Sub "${AWS::StackName}-BucketName"
```

## Creating a Stack

### Using AWS Console

1. Navigate to CloudFormation in AWS Console
2. Click "Create stack"
3. Upload your template (YAML or JSON)
4. Configure parameters
5. Review and create

### Using AWS CLI

```bash
# Create stack
aws cloudformation create-stack \
  --stack-name my-stack \
  --template-body file://template.yaml \
  --parameters ParameterKey=EnvironmentType,ParameterValue=prod

# Update stack
aws cloudformation update-stack \
  --stack-name my-stack \
  --template-body file://template.yaml \
  --parameters ParameterKey=EnvironmentType,ParameterValue=prod

# Delete stack
aws cloudformation delete-stack --stack-name my-stack
```

## Key Features

| Feature | Description |
|---------|-------------|
| **Drift Detection** | Detect manual changes to resources |
| **Change Sets** | Preview changes before applying |
| **Stack Sets** | Deploy across multiple accounts/regions |
| **Nested Stacks** | Modularize complex templates |
| **Rollbacks** | Automatic rollback on failure |

## Best Practices

1. **Use parameters** - Make templates reusable
2. **Enable termination protection** - Prevent accidental deletion
3. **Use IAM roles** - Follow least privilege
4. **Implement drift detection** - Detect manual changes
5. **Use outputs** - Share resources between stacks

## CloudFormation vs Terraform

| Aspect | CloudFormation | Terraform |
|--------|----------------|-----------|
| Provider | AWS only | Multi-cloud |
| State | AWS-managed | User-managed |
| Syntax | YAML/JSON | HCL |
| Updates | Direct | Plan/Apply |

## Conclusion

CloudFormation is essential for infrastructure as code on AWS. It provides a declarative way to manage your AWS resources with built-in rollback and drift detection.
