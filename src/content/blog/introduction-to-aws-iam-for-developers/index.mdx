# Introduction to AWS IAM for Developers

AWS Identity and Access Management (IAM) is the foundation of AWS security. Understanding IAM is essential for any cloud developer. This guide covers everything you need to know.

## Core Concepts

- **IAM Users** - Long-term credentials for people
- **IAM Roles** - Temporary credentials for services/applications
- **IAM Policies** - JSON documents that define permissions
- **Groups** - Collection of users with shared permissions

## Policy Structure

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3Read",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    }
  ]
}
```

## Best Practices

### 1. Use Roles Instead of Access Keys

```typescript
// ❌ Don't use long-term access keys
const credentials = {
  accessKeyId: "AKIA...",
  secretAccessKey: "..."
};

// ✅ Use IAM roles with temporary credentials
const { credentials } = await sts.assumeRole({
  RoleArn: "arn:aws:iam::123456789012:role/MyRole",
  RoleSessionName: "my-session"
});
```

### 2. Follow Least Privilege

```json
{
  "Effect": "Allow",
  "Action": [
    "dynamodb:GetItem",
    "dynamodb:Query"
  ],
  "Resource": "arn:aws:dynamodb:us-east-1:123456789012:table/Users"
}
```

### 3. Enable MFA for Sensitive Operations

```json
{
  "Effect": "Deny",
  "Action": ["s3:DeleteObject"],
  "Resource": "arn:aws:s3:::prod-bucket/*",
  "Condition": {
    "Bool": { "aws:MultiFactorAuthPresent": "false" }
  }
}
```

## Common IAM Patterns

| Pattern | Use Case |
|---------|----------|
| Service Role | Lambda function accessing DynamoDB |
| Cross-Account Access | Access resources in another AWS account |
| Federation | SSO with Okta/Google |
| Temporary Credentials | Short-lived access for mobile apps |

## Security Checklist

- [ ] Enable MFA for root account
- [ ] Use IAM roles, not access keys
- [ ] Implement least privilege policies
- [ ] Review unused credentials regularly
- [ ] Enable CloudTrail logging
- [ ] Use AWS Organizations for multiple accounts

## Conclusion

IAM is critical for AWS security. Master these concepts early, and follow security best practices to keep your cloud infrastructure safe.
